An agent layer on Excalidraw

Agents write native Mermaid. Mermaid parses it, elkjs lays it out, and Excalidraw draws it and lets people edit it. A thin bridge of our own merges each compile into the live canvas without undoing anyone's hand edits. Board edits flow back into the text as minimal edits, and every geometry defect comes back as a lint with element ids and a named fix. The agent reads text and short feed lines, never scene JSON.

What it unlocks

Eight things an agent and a human can do together that no tool we tested allows. Each one answers a pain the dogfood testers hit. The tag says when it lands.

  1. Hand edits survive re-layout. A dragged node stays where the human put it, and new nodes are placed around it.Pain 2: hand routes were flattened on every endpoint move. draw.io and Eraser reset positions when the source changes.by eval
  2. One call inserts a node into a busy diagram and reports what moved.Pain 5: inserting Surge took 7 manual moves. Testers estimated 9 applies and 8 screenshots dropping to 3 and 3.by eval
  3. Geometry defects come back as lints with ids, a box and a named fix.Pain 1: all ~15 first-pass defects were found by eye in PNGs. Nothing in the text output showed them.by eval
  4. Board edits become text edits. A relabel, a bound arrow or a delete on the canvas becomes a one-line change in ride.mmd.No product we surveyed lifts hand edits into minimal source edits. Mermaid Chart rewrites the whole file.by eval
  5. The agent sees what the human changed, with author and time, as short feed lines.Pain 6: a human edit was found only because a tester happened to diff its own export.by eval
  6. Turns stay cheap. The agent writes Mermaid, gets a ~100-token reply and asks for an image only when a lint needs one.Pain 9: add echoed the whole 18–20 KB scene. Pain 8: the one full-canvas PNG made 14 px text unreadable.by eval
  7. Sketches sit beside generated diagrams. Freeform shapes stay freeform, get linted and can be promoted with adopt.Mermaid has no way to add anything it did not generate. Sketching beside a diagram is the tutoring loop.by eval
  8. Several families on one canvas. Class, ER, state and requirement come first. Sequence, gantt and timeline follow, and each can nest inside a flowchart zone.ELK has no axis for time or message order, so we write a small layouter per axis family, the way D2 and yFiles do.steps 6–7

Design goals

Seven goals, each tied to the mechanism that meets it.

Reuse, don't rewrite
Mermaid parses, elkjs lays out and Excalidraw renders and edits. We write only the bridge between them: about 2,480 lines before the eval.
Text is meaning
ride.mmd holds what the diagram says. ride.excalidraw holds how it looks. Text and bindings lift into the .mmd. Geometry and style stay in the scene.
Identity is stable
Node ids are the Mermaid ids. Edge ids come from e1@, otherwise from from->to[#n] in source order. An element counts as generated only if its id equals the derived id.
No silent loss
A three-way merge over field-group hashes keeps every canvas change and reports it as an override or a conflict. Drags become soft pins, and moves are reported before they are committed.
Cheap agent turns
The agent reads the .mmd plus feed lines. apply returns counts and ids. look renders a crop only on request.
Rendered truth
Text is measured in Excalifont, the font the canvas draws with. Lint runs on the rendered boxes and routed points, not on the stored fields.
Not bound to Excalidraw
The core never imports a backend. Everything backend-specific sits behind BackendAdapter and Capabilities, and a fake backend in CI enforces the split.

Architecture

One IR carries changes in both directions. Text goes down to the canvas through the tree, and board edits come back up through the same tree. The canvas is never serialised straight to text.

When a file is opened and its hash does not match (the .mmd was edited since the last compile), the compile is seeded from the scene. Matching ids keep their geometry and overrides, and the reply reports the mismatch.

The backend seam

The core talks to a canvas through one interface. NeutralScene elements carry the backend's raw metadata as an opaque value. The "generated iff the id matches the derived id" rule is core logic, so each adapter does not implement it again. The seam normally hides five Excalidraw specifics: storage of gen in customData, frames that cannot nest, bound text as a separate #label element, binding semantics and Excalifont measurement.

  • backends/excalidraw first. It is the only editable backend before the eval passes.
  • backends/fake in CI: ~80 lines, nesting: "deep", bindings: "none". It is the second implementation that makes the interface worth having, because it takes the capability branches Excalidraw never takes.
  • draw.io (Apache-2.0) second, after the eval. tldraw needs a licence decision: since SDK 4.0, production use needs a key. SVG and JSON Canvas are export-only.
  • Comment threads stay app chrome for each backend. They remain neutral for free, because Thread.targetIds are element ids and a generated element's id is its model id.

How it works

Seven parts, in the order data flows through them.

Text format: native Mermaid plus %% directives

Valid Mermaid 11.17.2 is valid input. Our additions live in %% comments, which stock Mermaid ignores, so the same file still renders there. This is the dogfood ride-hailing diagram, trimmed:

@pin
A hard pin, absolute or relative (rightOf:rider gap:80). A human drag is a soft pin and lives only in the scene. export --pins can write drags out as @pin when asked.
@labelAt
Where an edge label sits on its routed path, from 0 to 1. It is the fix handle for label collisions.
@allow
Suppresses one lint rule on one element and must give a reason. Suppressed hits are still reported, with the reason.
@eject
Stops generating an element. It keeps its current geometry and style, edges stay bound to it, and the rest of the diagram stays generated.
@tombstone
Only for content the file cannot edit: an element from an @include or an instance. Ordinary deletes simply remove the line.
@include
@include ./core.mmd as core namespaces ids as core:trip. Step 8.
@note
A note anchored to an element that follows it through re-layout. Mermaid has notes only in sequence and state.

Roles are class names. A theme is a classDef block we ship, so an agent that names a theme writes no colours at all. Unknown shapes fall back to a rectangle with a validate warning, so new Mermaid syntax never breaks a file.

IR: one ElkNode tree, and ids

Model and layout are one tree. Its types extend elkjs's own .d.ts and add a typed meta bag to every node, edge, label and port. elkjs reads the tree and returns it natively, with meta preserved (probed). Nesting is unlimited. The tree has two explicit phases. Graph comes from the text and has ids, meta and sizes but no positions. LaidGraph is the same type after layout, with x, y and edge sections. Diff and the printers run on semantic(tree), a view that masks geometry and layoutOptions, so a re-layout never counts as a change.

ELK child coordinates are relative to the parent, and Excalidraw's are absolute. The adapter converts between them, with a test. read rebuilds zone parentage from meta, never from frameId. Presentation keeps only what the tree cannot hold: freeform elements, anchors and style overrides, all keyed by model id.

Layout: ELK for order, a one-axis placer for coordinates

The graph families run elkjs in-process under Bun, through elk-api.js and a Web Worker on elk-worker.min.js. The bundled build does not load under Bun (probed). The root sets elk.hierarchyHandling: INCLUDE_CHILDREN; without it, an edge into a zone's child comes back with no route. Subgraphs are compound nodes, so zones grow to fit their children.

ELK's interactive mode keeps order, not coordinates. In a probe, a node at x=400 came back at x=162, and the choice-constraint options are ignored. So a human drag cannot survive through ELK alone, and there are two modes:

No soft pins
Nobody has moved anything. Run ELK interactive and take its coordinates wholesale: best quality, small jumps. relayout: true always takes this path and clears soft pins.
Soft pins present
Run ELK interactive, but take only each new node's layer and rank. Kept nodes keep their canvas coordinates. A new node goes into the gap between its layer neighbours. If the gap is too small, the placer pushes everything downstream in that zone along the flow axis by the shortfall. Order is preserved, and every move is reported in moved[].

Routing. ELK's edge sections are valid only for coordinates ELK chose, so:

  • When ELK's coordinates are applied, every edge uses ELK's routes.
  • After a placer apply, untouched edges keep their routes. In v0, edges touching a moved or new node are redrawn as straight bound arrows, and lint flags any arrow-through-node. Excalidraw's bindings keep arrows attached between applies.
  • From step 7, libavoid-js reroutes those edges. It also routes gantt dependencies, hard pins and drags, and an incremental reroute takes ~5 ms. It is LGPL-2.1, so it ships as a separate, unmodified WASM file loaded server-side only, never inlined into the MCP App bundle. It needs a parity fixture and nudging-distance tuning before we trust it.

Diagram families

Graph families go through Mermaid's unified getData() and then ELK. Axis families lay out along a metric or ordinal axis that ELK cannot express, so each gets its own layouter that fills x, y and sections itself. They use the same tree type but no ELK call, since ELK's fixed algorithm only copies positions and does not route.

Composition. An axis family nested in a flowchart zone becomes an ELK fixed compound. It sets SEPARATE_CHILDREN (allowed under the root's INCLUDE_CHILDREN) and has FIXED_POS ports on its boundary for edges from outside. ELK sizes and places the compound, and routes the outer edge to the port.

Axis-family lift reverses the graph rule: there, geometry is meaning. Dragging a message past its neighbour reorders it. Dragging a participant sideways reorders the participants. Dragging a gantt bar changes its start, snapped to the axis unit, and dragging its right edge changes the duration. Dropping a timeline event on a period moves it. Every lift map snaps, so a two-pixel drag never becomes a semantic edit, and lint rules are gated by meta.family, since a gantt bar overlapping its band is correct.

Merge and lift

Merge. The compiler writes meta.gen on each generated element: hashes of its geometry, style and text as last written. On apply, each group is compared three ways, so no shadow copy of the last output is stored anywhere:

canvas = gen, new = gen
No-op.
canvas = gen, new ≠ gen
Write the new value and update gen.
canvas ≠ gen, new = gen
Keep the canvas value and report an override.
canvas ≠ gen, new ≠ gen
Keep the canvas value and report a conflict. force: true writes the new one.

Generated elements that the text no longer declares are deleted within the prune scope (the diagram by default) and reported otherwise. eject turns a generated element into a plain one that keeps its geometry. adopt promotes a human element into the text with a stable id, using copiedFrom when it has one.

Lift. On each human save, the scene is diffed against the last compile through the same hashes. The rule: text and bindings are meaning; geometry and style are presentation; freeform stays freeform until it is adopted.

Lift rules for graph families
Human editResultWritten to
Move or resize a generated elementSoft pinScene only; export --pins can emit @pin

Lifts produce AstPatch operations: create, set, reconnect, delete, rename and move. The vocabulary is copied from D2's d2oracle. In Mermaid, the id and the label are separate tokens (trip[Trip]), so a label lift never changes an id. rename comes only from the agent or the text, and the printer rewrites every occurrence.

Lift is symmetric with undo. An Excalidraw undo reverts the scene, and the next lift reverts the text. Writes to the .mmd are coalesced (the 1.5 s save debounce plus a few quiet seconds), so typing a label does not churn the file, and each lift emits one feed line. Proposals are comment threads with one new field, Thread.proposal?: {kind: "adopt" | "edge" | "patch", patch} (CONTRACT v1.5, bumped when this is built). Accepting one applies the patch and resolves the thread; rejecting it just resolves the thread. The agent uses the same mechanism to propose changes to the human.

Suppression is allow: [{rule, why}] on one element, with a required reason and no wildcards. Lint reads it from meta, so the same mechanism works on human elements.

Diff comes in four forms, and none of them is a pixel diff. A pixel diff cannot name ids or authors, and ids and authors are what the pair loop needs.

  • Semantic: a text diff of the canonical .mmd. The canonical printer sorts and writes one statement per line, so two exports of the same model are byte-equal.
  • Feed: lift and event lines such as h 14:02 relabelled core:trip "Trip" → "Trips svc" or h 14:05 freeform h7 text "why is Redis here?" near core:redis.
  • Lint delta: for example, "+2 crossings, −1 label collision". cv diff A B works on any two versions and compiles both sides with pure layout, so the result is deterministic.
  • Visual, on request: look --before rev --after rev renders the same crop side by side.

Agent surface and token budget

One engine sits behind a thin CLI and a thin MCP adapter, delivered in step 2b. The existing MCP server gains apply, lint, look and diff and keeps its v1.4 tools. Why it beats Mermaid, Excalidraw and the existing MCPs

Each competitor does one part well. What none of them has is the combination: pins, incremental re-layout around them, edits lifted into minimal .mmd changes, and a surface built for agents.

Build plan

The eval is the go/no-go

One Opus tester re-runs the two dogfood tasks through .mmd with the same prompts: the ride-hailing architecture (draft, insert Surge, move Pricing) and the dense BST figure. Go when all four hold for each task:

  • Tool calls ≤ ⅓ of the dogfood's count.
  • Tokens (input + output, images at the usual rates) ≤ ⅕ of the dogfood's.
  • 0 lint errors left unfixed at the end.
  • Defects found by eye on the final PNG that lint missed: 0 on ride-hailing, ≤ 1 on the BST.

Go: proceed to steps 6–8; draw.io becomes eligible as a second editable backend. No-go: one fix cycle on steps 2–4, scoped to the failing measure (typically the reply format or a missing lint rule), then re-run the eval once. A second no-go stops the layer and keeps v1.4 as the product.

The Mermaid 12 upgrade is an ordinary task gated by the parity suite. Mermaid 12 bundles ELK and makes it the default, which may let its bundled copy replace our direct elkjs dependency.
